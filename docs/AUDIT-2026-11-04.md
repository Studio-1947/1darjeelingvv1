# aangan end-to-end audit (4 Nov 2026)

Checked against the "Aangan review" doc, the FigJam blueprint ("Aangan Blue Print") and the mobile app repo.

## How it was checked

- The code was read for every review-doc item (35) and every blueprint flow (A–N).
- The automated browser walks were run against a fresh local stack with 28 sample listings:
  - `tests/walk/host-live-walk.cjs` took all 5 host types from sign-in, through payment, profile, documents and admin approval, to a public listing. **All 5 went live.**
  - `tests/walk/site-walk.cjs` opened every page as guest, traveller and host, at phone and desktop width, and followed 105 internal links. **No problems found.**
- Test suites: backend 754 tests, website 55 tests.
- GitHub Actions results were checked for `prod`.
- The mobile app repo (`1-Darjeeling-Mobile-App`) was checked for its branches, payment handling and feature parity.

Results: 33 of the 35 review items are done. The blueprint is largely built. The gaps that are left are listed below, most urgent first.

## P0: fix first (money or live site)

### 1. The live site has not deployed since PR #223 *(fixed on `fix/ci-green`; merge to deploy)*
- PR #224 (admin deliveries, guide services, website verification fixes) was merged during the GitHub outage and never deployed.
- PR #225 (points) was merged next, but the deploy stopped at "Backend tests". Nothing was shipped.
- The cause was not #224 or #225 as such. `backend/test/verificationSent.test.ts` uploads a document without stubbing storage. CI has no MinIO, so the upload returns 503 and the test fails.
- Two more checks were also red on PR CI:
  - The website's `yarn test` also ran the Playwright file `e2e/app-shell.spec.ts`.
  - The admin panel's `npm audit` flagged a high-severity `follow-redirects` advisory.
- All three are fixed on `fix/ci-green`. **Merging it deploys #224, #225 and these fixes together.**

### 2. The mobile app in the stores cannot take payments from travellers
- Store builds are 1.1.0, built from `main`. They check the server's order amount against hardcoded prices:
  - pass: expected ₹14.40, server charges ₹14.16 or ₹116.82
  - ₹1 fee: expected ₹1.20, server charges ₹1.18
- So **a traveller without a pass cannot buy the pass or pay the ₹1 fee in the app, and cannot finish a booking there.** Host payments still work.
- The fix already exists on app branch `feat/board-gaps` (PRs #16, #17 and #18, none merged into `main`). To ship it:
  1. Push the unpushed commit `cbc7498` on `feat/board-gaps`.
  2. Merge `feat/aangan-review-fixes` (#16, which includes #17) and `feat/board-gaps` (#18) into `main`.
  3. Bump `version` (for example to 1.2.0) and `versionCode`/`buildNumber` in `app.json`. They are still 1.1.0 / 26102801.
  4. Build with EAS and submit to Play (and the App Store).
  5. Once the build is live, set `APP_MIN_VERSION` and `APP_LATEST_VERSION` to the new version on the server, so 1.1.0 users are told to update.
- Recommended: make the app check amounts against the server's own `breakup`, not a hardcoded list, so the next price change cannot break it.
- The local `main` in the app repo is 18 commits behind `origin/main`. Don't build from it.

### 3. Bookings never wait for host approval *(needs a product decision)*
- Blueprint (K, M): "Book → Waiting for approval → Call/WhatsApp". For guides: "based on availability, confirm".
- The website books and confirms in one step: `useBookingFlow.ts` calls `/bookings`, then `/checkout` straight away.
- The server's `/checkout` does not require the host to accept first.
- Hosts have no **Accept** button. `BookingCard.tsx` has only Call, WhatsApp and Decline, though the server already has `PATCH /bookings/:id/confirm`.
- To match the board:
  1. Booking creates a request.
  2. The host gets an Accept button.
  3. The guest pays the ₹1 fee (or uses the pass) after the host accepts.
  4. Checkout refuses until the booking is `accepted`, for drivers, homestays and guides.
- The app needs the same change.
